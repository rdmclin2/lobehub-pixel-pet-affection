### 1.2 下一层：分组、页面、层级（树状前后对照）

**现状**（`src/core/settings-schema.js` 的 `RAIL` / `NAV`）：

```
小屋 #/overview
角色 #/characters ─ 角色详情 #/characters/:id（标签：装扮/好感/模型/个性化设定/语音/资料，标签不进 URL）
商店 #/store ─ [标签栏只有「角色」]
玩法 #/play（Hub）
 ├ 陪伴方式：桌宠行为 #/behavior · 主动搭话与好感 #/proactive（含插个嘴+两张表） · 同屏伙伴 #/visitors
 └ 和她一起：话题 #/topics · 聊天记录 #/history · 桌面上的她 #/desk（含退出应用）
设置 #/settings（Hub）
 ├ 声音：朗读 #/tts · 语音输入 #/asr · 语音包 #/voicepacks
 ├ 资源与外观：角色包 #/packs · 外观主题 #/appearance
 ├ 连接：LobeHub 与本机 #/connection（账号+本机能力+重新开始话题） · 对外接口 #/api
 └ 系统：内容与安全 #/safety · 版本与更新 #/update · 数据与关于 #/about（含危险操作）
聊天 #/chat/:id
未知路由 → 静默显示小屋
```

**优化后**：

```
小屋 #/overview          舞台 + 关系 + 今天的陪伴（状态句）+ 遇见过的伙伴（按角色聚合）
角色 #/characters?kind=  图鉴：按「角色」列卡片（一位一张），筛选进 query
 ├ 角色详情 #/characters/:id/:tab   tab ∈ looks 装扮 · model 模型 · role 个性化设定 · affection 好感 · about 资料与语音
 │   └ 页底 DangerZone：删除下载 / 一键解锁 / 清空设定
 └ 角色包 #/packs         （从 设置 挪来）按角色分组的父行 + 形象子行；导入 / 导出 / 删除
聊天 #/chat/:id          会话栏只列已遇见的角色 + 「结识更多」；含历史（原聊天记录）与「重新开始对话」
商店 #/store?show=       单类别时不显示标签栏
──────────
玩法 #/play（Hub）
 ├ 她怎么陪你（设置）：桌宠行为 #/behavior · 主动搭话与好感 #/proactive · 插个嘴 #/interject（新） · 同屏伙伴 #/visitors
 └ 和她互动（操作）：话题 #/topics · 桌面上的她 #/desk（动作 + 找回桌宠）
设置 #/settings（Hub）
 ├ 声音：朗读与音效 #/tts（按引擎渐进展开 + 试听） · 语音输入 #/asr · 语音包 #/voicepacks
 ├ 隐私与安全：成人向与本机能力 #/safety · 对外接口 #/api · 重置与放生 #/reset（新）
 └ 系统：账号与连接 #/connection · 版本与更新 #/update · 关于与数据 #/about（主题、硬件加速、数据目录、素材署名折叠、退出应用）
未知路由 → 「没有这个页面」空态（回小屋 / 去设置）
旧路由兼容：#/history → #/chat/<当前角色>；#/appearance → #/about；#/characters/:id → #/characters/:id/looks
```

层级深度：现状最深 3 层（rail → Hub → 页面），优化后不变；角色详情从「2 层 + 页内状态」变成「2 层 + URL 标签」（P-03）。设置 Hub 分组 4 → 3，卡片 10 → 9；玩法 Hub 卡片 6 → 6（−聊天记录 +插个嘴）。

## 2. 全局反馈与状态规范（所有流程共用）

下面 7 条是全窗口的统一做法，§3 每个流程的「状态设计」引用这里的编号（S-1～S-7），避免每个页面各写一套。

| 编号 | 状态 | 统一做法 | 组件（不新增原子） | 依据 |
| --- | --- | --- | --- | --- |
| S-1 | 加载 | 首次读取：数据所在的表面显示 `Skeleton` / `Table loading`；按钮触发的请求：按钮自己 `loading`，请求结束前不弹任何提示 | `@lobehub/ui` `Skeleton`、`Button loading` | K-05 状态与反馈 |
| S-2 | 空态（三种分开） | ① 首次使用：说明 + 第一个动作按钮；② 筛选后为空：「没有符合条件的…」+ 清除筛选；③ 前置条件不满足（未唤醒）：共享组件 `NoPet`，主按钮「打开桌宠窗口」（`api().showPet()`） | `Empty` + `Button` | W-04 空态文案、M-06（缺能力 A） |
| S-3 | 错误（读取） | 失败 ≠ 零条：表格 / 列表位置显示 `LoadFailed`（原因 + 「重试」），不显示空态文案；不靠可关闭的页顶 Alert | `Empty`（`type=error` 文案）+ `Button` | K-05「失败不是零条」、W-05 错误文案 |
| S-4 | 错误（写入） | 所有写操作按返回的 `ok` 分支：成功走 S-5，失败 `toast.error({ title: 没能<动作>, description: 原因 + 怎么办 })`；禁止只写「操作失败 / 检查失败」 | `toast.error` | W-05、C-15 |
| S-5 | 保存成功 | 即时项（开关 / 下拉 / 分段 / 滑块，**以及改造后的数字项**）：成功**不弹 toast**，控件旁内联 1.5s「已保存」（`Text type=success` + `Check` 图标）；需重启的项：`toast.warning`（稳定 id `restart`，原地刷新）「重启后生效」+「立即重启」；Key / URL / 文本：保留显式「保存」，成功后输入框旁标签由「未设置」变「已设置」 | `Text`、`Icon`、`toast`（`id`） | C-17 表单就地编辑、K-05「toast 用稳定 id 原地刷新」、P-05 |
| S-6 | 未保存与离开 | Key / URL / 文本草稿未保存时：字段下「未保存的修改」保持；离开页面（rail、面包屑、hash 变化）前统一弹 `confirmModal`「放弃未保存的修改？」（okText「放弃修改」、cancelText「留在这里」） | `confirmModal`（R-03） | P-04 离开提醒 / 草稿、P-05「未保存修改可见」 |
| S-7 | 危险确认 | 不可逆操作统一 `askAsync(title, desc, okText, run)`：确认弹窗内执行，按钮显示进行中，提交期间不可关闭；失败把原因写在弹窗里、弹窗不关；成功才关闭并写出实际结果（如「删除了 3 个 agent」）。**可撤回**的操作（字段恢复默认、页恢复默认）不弹确认，执行后 toast 带「撤销」（5s） | `confirmModal`（`okText` / `cancelText` 必传，R-03）；若其 `onOk` 不支持 Promise 则用 `Modal` + `confirmLoading` 封装 | C-15 确认弹窗、W-06 确认与占位、W-07「确认框保护的是可撤回的操作 → 改为执行后提供撤销」 |

共享件（由 A 包先建，B / C 包引用）：`NoPet`、`LoadFailed`、`askAsync`、`useLeaveGuard`、`SavedHint`，以及 B 包建的 `roster-model.ts`（角色 / 形象计数与状态词）。

### F7 开关对外接口、成人向内容、本机能力（T-6）

4. 三个高风险开关散在 2 组 3 页，入口名看不出风险（HUB-02）。

**优化后路径**
1. 设置 → **隐私与安全** 一组集中：成人向与本机能力（`#/safety`）、对外接口（`#/api`）、重置与放生（`#/reset`）。Hub 卡片状态一句话：「成人向：关 · 本机能力：关」「对外接口：监听中 127.0.0.1:7340」。

## 5. 落地拆分：A / B / C 三个实施包

### 5.1 分包原则与对任务给定分包的调整说明

任务给定的分包按**文件**切（A：Shell / Home / Hub / Pages / SettingsForm / fields；B：Characters + stage；C：Chat / Interject / Together / Store）。01-issues §4 按**问题主题**切成 5 包。本方案采用任务给定的 3 包，但做了以下 4 处调整，否则会出现两个包同时改一个文件、或前后依赖打结：

1. **`src/core/settings-schema.js`（RAIL / NAV / PAGES / FIELDS 的 page/card）全部归 A**。B 的「角色包挪到角色」（SH-01）、C 的「插个嘴独立页」「聊天记录合并」（INT-01、SH-02）涉及的导航数据由 A 一次改完；B / C 只改页面组件。理由：schema 是唯一的导航数据源（R-05「rail = `RAIL`」），分散修改会冲突，e2e A3 也只需改一次。
2. **全局共享件由 A 先建**：`NoPet`、`LoadFailed`、`askAsync`、`useLeaveGuard`、`SavedHint`（§2）。B、C 的错误态 / 危险确认依赖它们，所以 A 的「A00 共享件」是三个包的第一步。
3. **对象模型 `roster-model.ts`（计数口径 + 状态词）归 B**，A（Home、Hub）与 C（Chat、Store）引用。理由：它的定义与图鉴卡片四态一体（CHAR-01、STORE-02、STG-03、CHAT-02）。
4. **`PacksPage` 虽然挂在设置导航里，但代码在 `Characters.tsx`，归 B**；**TOG-04 涉及 `Pages.tsx` 桌宠行为页的「找回桌宠」按钮，由 C 负责（删除那个按钮是 C11 的一部分）**，A 不改该按钮，避免冲突。语音包页（`Pages.tsx`）归 A。

**顺序**：A00（共享件 + schema）→ B01 / B02（对象模型、详情路由）→ A 其余、B 其余、C 并行。A08（小屋按钮直达标签）依赖 B02；C02 / C14 依赖 B01。
